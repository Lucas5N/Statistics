From Wallet Seed to Ethereum Address

This page follows the main steps an Ethereum wallet uses, starting from a BIP-39 mnemonic and ending with an EIP-55 checksummed address.

Wallet input

Use only public test mnemonics, never a mnemonic controlling real cryptocurrency.

Ethereum wallet pipeline

BIP-39 — Mnemonic → Seed

BIP-39 turns wallet entropy into a list of words and adds a checksum. The mnemonic is then converted into a 512-bit seed using PBKDF2-HMAC-SHA512 with 2048 iterations.

BIP-32 / BIP-44 — Seed → Private Key

BIP-32 lets one seed generate a whole hierarchy of keys. BIP-44 gives the derivation path a standard structure, and coin type 60 is used for Ethereum.

secp256k1 — Private Key → Public Key

The private key is used in elliptic-curve scalar multiplication to get the public key. Ethereum uses the secp256k1 curve for this and for digital signatures.

Keccak-256 — Public Key → Hash

For an uncompressed public key, Ethereum removes the first prefix byte and hashes the remaining 64 bytes, which contain the x and y coordinates, with Keccak-256.

Ethereum Address

The Ethereum address is made from the last 20 bytes of the 32-byte Keccak-256 hash, so the address itself is 160 bits long.

EIP-55 — Checksummed Address

EIP-55 changes the case of some hexadecimal letters in the address. This acts as a checksum and helps catch typing or copying mistakes.

Different cryptographic roles

Key generation

Key generation is where the wallet gets new random secret material. In this case, random entropy is the starting point for creating a mnemonic.

Key derivation

BIP-32 and BIP-44 derive keys from an existing seed in a deterministic way. If the seed and path are the same, the private key will also be the same.

Public-key cryptography

secp256k1 gives the mathematical link between the private key and the public key. It is also the curve Ethereum uses for signatures.

Hashing

Keccak-256 takes input data and produces a fixed 256-bit result. A good cryptographic hash should be hard to reverse and hard to find collisions for.

Checksum

EIP-55 uses uppercase and lowercase letters as a simple checksum, so many accidental address errors can be detected.

Encoding

Encoding changes the representation of data without changing what the data means. Here, examples are mnemonic words, hexadecimal keys and the mixed-case EIP-55 address.

Statistical properties

A 12-word BIP-39 mnemonic contains 128 bits of entropy and a 4-bit checksum. A 24-word mnemonic contains 256 bits of entropy and an 8-bit checksum.

The BIP-39 seed is 512 bits long. A secp256k1 private key is about 256 bits and is usually considered to give around 128 bits of classical security. Keccak-256 outputs 256 bits, while an Ethereum address keeps 160 bits. EIP-55 adds about 15 checksum bits on average.

One useful property of a cryptographic hash is the avalanche effect. If one input bit changes, roughly half of the output bits should change too.

SHA-2, Keccak and SHA-3

SHA-512 is part of the SHA-2 family. BIP-39 uses it inside HMAC and PBKDF2 when the mnemonic is turned into a seed.

Keccak is a different hash design. It was chosen as the basis for the SHA-3 standard.

Ethereum uses Keccak-256, not the standardized SHA3-256 function. The two are closely related, but their padding rules are different, so the same input does not give the same hash.

Why are several techniques needed?

These techniques are used together because they do different jobs. BIP-39 deals with the mnemonic and seed, BIP-32 and BIP-44 derive keys, secp256k1 connects private and public keys and is used for signatures, Keccak-256 hashes the public key, and EIP-55 adds error checking to the final address. No single algorithm is meant to do all of these things.
