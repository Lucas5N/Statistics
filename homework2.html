From Wallet Seed to Ethereum Address

This page shows the main cryptographic steps used by an Ethereum wallet, from a BIP-39 mnemonic phrase to an EIP-55 checksummed address.

Wallet input

Use only public test mnemonics, never a mnemonic controlling real cryptocurrency.

Ethereum wallet pipeline

BIP-39 — Mnemonic → Seed

BIP-39 encodes entropy as human-readable words with a checksum. The mnemonic is converted into a 512-bit seed using PBKDF2-HMAC-SHA512 with 2048 iterations.

Different cryptographic roles

Key generation

Key generation creates new random secret material. For example, a wallet begins with random entropy from which a mnemonic can be generated.

Key derivation

BIP-32 and BIP-44 deterministically derive keys from an existing seed. The same seed and path always produce the same private key.

Public-key cryptography

secp256k1 defines the mathematical relationship between private and public keys and is used for digital signatures.

Hashing

Keccak-256 maps input data to a fixed 256-bit value. Hashing is designed to be one-way and collision resistant.

Checksum

EIP-55 uses capitalization to detect many accidental errors when copying or typing Ethereum addresses.

Encoding

Encoding changes how information is represented. Examples include mnemonic words, hexadecimal keys and the mixed-case EIP-55 address format.

Statistical properties

A 12-word BIP-39 mnemonic represents 128 bits of entropy plus a 4-bit checksum. A 24-word mnemonic represents 256 bits of entropy plus an 8-bit checksum.

The BIP-39 seed contains 512 bits. secp256k1 private keys are approximately 256-bit values and provide roughly 128 bits of classical security. Keccak-256 produces a 256-bit hash, while an Ethereum address contains 160 bits. EIP-55 provides about 15 checksum bits on average.

A cryptographic hash should display the avalanche effect. Changing a single input bit should cause approximately half of the output bits to change.

SHA-2, Keccak and SHA-3

SHA-512 belongs to the SHA-2 family. BIP-39 uses SHA-512 inside HMAC and PBKDF2 when deriving the seed from the mnemonic.

Keccak is a different cryptographic hash design and was selected as the basis of the SHA-3 standard.

Ethereum uses Keccak-256 rather than the standardized SHA3-256 function. They are closely related, but use different padding and domain-separation conventions, so the same input produces different results.

Why are several techniques needed?

The different technologies solve different problems. BIP-39, BIP-32 and BIP-44 handle key representation and deterministic key management. secp256k1 provides the private/public key relationship and digital signatures. Keccak-256 provides cryptographic hashing. EIP-55 provides error detection for addresses. A single algorithm would not perform all of these different roles.
