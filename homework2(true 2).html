1. Toy elliptic-curve encryption

This experiment uses the secp256k1 elliptic curve. To make an attack computationally feasible, the private key is intentionally restricted to the range 1–5000. This is a toy ECIES-like construction and not a complete real-world encryption protocol.

Main steps

1. The receiver chooses private key d. 2. The public key is Q = dG. 3. The sender chooses a random temporary scalar r. 4. The sender calculates R = rG and the shared point S = rQ. 5. S is converted into a keystream using SHA-256. 6. The message is XORed with the keystream. 7. The receiver calculates the same S = dR and decrypts the ciphertext.

Role of the keys

d is the receiver's private key and must remain secret. Q = dG is the public key and can be published. r is a temporary random value generated by the sender. R = rG can be sent publicly. Both sides independently obtain the same shared secret S without transmitting S itself.

3. Statistical cryptanalysis

English letters do not occur with equal probability. The attack tries all 26 Caesar shifts and compares the resulting letter frequencies with standard English frequencies using a chi-squared score. The candidate with the lowest score is selected as the most likely key.

Effectiveness

The attack normally becomes more reliable as the ciphertext gets longer because the observed frequencies become closer to the expected frequencies of English. With enough text, the correct shift usually receives the best statistical score.

Limitations

Very short ciphertexts can give misleading results. Unusual vocabulary, names and non-English text can also reduce accuracy. The attack assumes that the language and its approximate frequency distribution are known.

Exhaustive search

Caesar has only 26 possible keys, so trying every key is extremely easy. Exhaustive search guarantees that the correct plaintext is among the candidates, although a human or another scoring method may still be needed to identify it.

Frequency vs n-grams

Single-letter frequency analysis is simple and fast but can struggle with short messages. An n-gram method scores common groups such as TH, HE or ING. It can often recognize natural language more accurately, but requires a larger language model.

4. Attack on the restricted ECC key

Because this experiment restricts d to only 5000 possible values, an attacker can calculate G, 2G, 3G, ... and compare each result with the public key Q. When a match is found, the corresponding value is the private key.

ECC brute-force attack

The ECC attack does not depend on the language or statistical properties of the plaintext. It exploits the artificially small private-key space. The attacker searches possible values of d until dG equals the public key Q.

Caesar statistical attack

The Caesar attack exploits information leaked by the ciphertext. A Caesar shift preserves the shape of the plaintext letter-frequency distribution, only moving the letters to different positions. The attack therefore uses properties of the language itself.

Proper secp256k1

Real secp256k1 private keys are selected from an enormous range close to 2²⁵⁶ possibilities. Searching a range of 5000 values is trivial, but performing the same exhaustive search over the normal key space is computationally infeasible. Generic elliptic-curve discrete-logarithm attacks are also vastly more expensive than the attack used in this experiment.

Other possible weaknesses

The small private-key range is an artificial weakness introduced for the homework. Other weaknesses could instead come from the design or implementation, for example predictable random values, reused temporary keys, side-channel leakage or incorrect point validation. This toy encryption also provides no authentication, so it should not be treated as a secure real-world protocol.

5. ECC vs Caesar cipher

Encryption and decryption

Caesar uses one shift value. Encryption adds the shift and decryption subtracts it. The ECC experiment uses a private/public key pair and a temporary sender value to create a shared secret used for encryption.

Key spaces

Caesar has only 26 possible keys. The toy ECC experiment has 5000 possible private keys because the range was deliberately restricted. Proper secp256k1 has an enormously larger private-key space.

Statistical properties

Caesar preserves plaintext statistics. A frequent plaintext letter remains frequent in the ciphertext, although it appears as another letter. The ECC-based construction creates a pseudorandom-looking byte stream from the shared secret, so the original letter frequencies are not directly preserved in the ciphertext.

Main similarity

Both systems require key material and both transform plaintext into ciphertext that can later be reversed by an authorized receiver. Their security assumptions, however, are completely different.
